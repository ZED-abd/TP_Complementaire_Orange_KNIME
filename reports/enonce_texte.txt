TP complémentaire : construire un workflow de 
Machine Learning avec Orange puis KNIME 
Partie I : Contexte & Objectifs Pédagogiques 
Ce TP accompagne le cours Cours_Complementaire_Machine_Learning_Visuel_Orange_KNIME.pdf. Il 
se fait à la maison, en autonomie. Il complète le TP04 (FLAML) sans le remplacer, et il est indépendant 
du TP05 officiel (MLflow, déploiement, Vertex AI), qui reste le travail de la séance 5.2. 
Vous reconstruisez le modèle de détection de fraude des TP sans écrire de code, d'abord dans Orange 
Data Mining, puis dans KNIME Analytics Platform, sur le même jeu de transactions. Vous terminez 
par une courte synthèse qui compare les deux outils entre eux et avec ce que vous avez obtenu avec 
FLAML au TP04. L'objectif n'est pas de trouver le meilleur score, mais de comprendre ce que chaque 
outil fait, ce qu'il ne fait pas, et ce qui reste à votre charge. 
Objectifs 
• Objectif 1 (Orange) :  charger les données, désigner la cible, partager apprentissage / test, 
comparer cinq algorithmes, améliorer, analyser les erreurs et sauvegarder. 
• Objectif 2 (KNIME) : construire le même processus avec des nœuds Learner / Predictor / Scorer 
et lire les statistiques par classe. 
• Objectif 3 (synthèse) :  comparer Orange, KNIME et FLAML sur la qualité, le temps, la 
reproductibilité et l'export du modèle. 
 
À RETENIR : Comment lire ce TP 
• Essentiel = à faire pour que le TP soit complet. Obligatoire = questions à rédiger dans le compte rendu. 
Bonus = pour aller plus loin, si tout le reste fonctionne. 
• Durée totale réaliste : environ 3 h pour l'essentiel et les questions, plus l'installation. Vous pouvez faire 
le TP en deux fois : Orange un jour, KNIME un autre jour. 
• Gardez le cours ouvert : la partie V explique les captures d'Orange, la partie VI celles de KNIME. 
 
Partie II : Prérequis & Configuration Requise 
• Le cours du module complémentaire lu (au moins les parties II à IV). 
• Le TP04 réalisé : vous avez le dossier tp4-automl et son fichier data/transactions.csv (5 000 
lignes, 568 fraudes). Sinon, l'Annexe A permet de le régénérer à l'identique. 
• Un poste Windows avec environ 3 Go d'espace libre et, pour KNIME, 8 Go de mémoire vive  
conseillés. 
• Une connexion internet pour les installations (KNIME pèse plusieurs centaines de Mo) et, pour le 
bonus B1, pour le KNIME Hub. 
À RETENIR : Règles pour tout le TP 
• Windows PowerShell ou le terminal intégré de VS Code pour les commandes, jamais cmd.exe. 
• Orange et KNIME sont des applications : ils lisent le fichier CSV, ils ne s'installent pas dans un 
environnement de TP existant. 
• Enregistrez régulièrement vos workflows (Ctrl + S) et faites les captures au fur et à mesure.

KNIME migre progressivement les fenêtres de configuration de ses nœuds vers une nouvelle interface :

3. Tirez un deuxième lien Data Sampler → Test and Score. La fenêtre Edit Links s'ouvre : tracez un trait 
de Remaining Data vers Test Data, puis OK. Les 25 % restants servent maintenant de jeu de test. (Pour

4. Catégorie Model : posez Logistic Regression, kNN, Tree, Random Forest et Gradient Boosting.

Étape 1.3 : Améliorer, analyser, sauvegarder 
Objectif : préparer les données pour l'algorithme qui en a besoin, lire les erreurs du meilleur modèle, 
puis sauvegarder le modèle et le workflow. 
1. Catégorie Transform : posez Preprocess. Ouvrez -le, glissez Normalize Features de la liste de 
gauche vers la zone de droite et gardez Standardize to μ=0, σ²=1 . Reliez Preprocess → kNN (sortie 
Preprocessor → entrée Preprocessor). Le kNN calcule des distances : sans normalisation, la colonne 
montant écrase toutes les autres. 
2. Ouvrez Random Forest : passez Number of trees de 10 à 100 (laissez Replicable training coché). 
3. Revenez dans Test and Score et relevez les nouveaux F1 du kNN et de la forêt. 
4. Catégorie Evaluate : posez Confusion Matrix , reliez Test and Score → Confusion Matrix et 
sélectionnez Gradient Boosting dans la liste. 
5. Pour obtenir un modèle utilisable hors de Test and Score : reliez Data Sampler → Gradient Boosting 
(lien Data Sample → Data) ; le widget sort alors un Model. Reliez-le à Save Model (catégorie Model), 
cliquez sur Save as… et enregistrez tp-lowcode/models/fraude-gb.pkcls. 
6. Menu File › Save As : enregistrez le workflow dans tp-lowcode/workflows/fraude-orange.ows.

Étape 2.1 : Créer le workflow et lire les données 
Objectif : lire le CSV et transformer la cible en catégorie. 
1. Lancez KNIME. Si l'interface « classique » s'affiche, cliquez en haut à droite sur le bouton qui ouvre la 
nouvelle interface (Modern UI). 
2. Sur la page d'accueil (onglet Home), ouvrez Local space, puis cliquez sur Create workflow (bouton 
« + »). Nommez-le tp-fraude. Un canevas vide s'ouvre. 
3. Dans le panneau Nodes à gauche, tapez CSV Reader dans la zone de recherche et glissez le nœud 
sur le canevas (nœud 1 du schéma). 
4. Double -cliquez sur le nœud pour le configurer. Avec Browse, choisissez tp-
lowcode/data/transactions.csv. Laissez le séparateur détecté (la virgule) et la ligne d'en-tête cochée. 
L'aperçu montre 5 colonnes ; fraude est de type nombre entier. Validez (OK ou Apply). 
5. Exécutez le nœud : touche F7, ou clic droit › Execute. Le feu passe au vert. Cliquez une fois sur le 
nœud : le moniteur du bas (node monitor) affiche la table lue. 
6. Cherchez le nœud Number to String, posez-le à droite et reliez la sortie du CSV Reader (petit triangle

SI ÇA COINCE 
Pourquoi convertir `fraude` en texte ?  Les nœuds d'apprentissage de classification de KNIME exigent 
une cible nominale (des catégories). Une colonne d'entiers est vue comme une quantité : elle n'apparaît 
pas dans la liste « Target column ». C'est l'équivalent du passage en categorical dans Orange. 
 
Étape 2.2 : Partager les données et entraîner trois modèles 
Objectif : reproduire le protocole d'Orange (75 % pour apprendre, 25 % pour tester), puis entraîner trois 
algorithmes et les appliquer au test. 
1. Posez Table Partitioner (nœud 3 ; Partitioning dans les anciennes versions) et reliez-le au nœud 2. 
Configurez : partition relative de 75 %, stratégie Stratified sur la colonne fraude, graine aléatoire fixe 
(fixed random seed) 42. Exécutez. Le port de sortie du haut contient les 75 % (apprentissage), celui du 
bas les 25 % (test). 
2. Posez Logistic Regression Learner (nœud 4) et reliez la sortie haute du partitionneur à son entrée. 
Target column : fraude. Exécutez. 
3. Posez Logistic Regression Predictor (nœud 5). Il a deux entrées : reliez le port carré (le modèle) à 
la sortie du Learner, et le port triangulaire (les données) à la sortie basse du partitionneur. Exécutez : la 
table de sortie contient une nouvelle colonne Prediction (fraude). 
4. Même chose avec Random Forest Learner  (nœud 7 : target fraude, Number of models  = 100, 
cochez Use static random seed) et Random Forest Predictor (nœud 8 : cochez Append individual 
class confidences, utile pour une courbe ROC). 
5. Même chose avec Gradient Boosted Trees Learner (nœud 10, réglages par défaut : 100 modèles, 
profondeur 4, taux d'apprentissage 0,1) et Gradient Boosted Trees Predictor (nœud 11). 
6. Astuce : pour gagner du temps, sélectionnez un couple Learner + Predictor, copiez-le (Ctrl + C, Ctrl + 
V), puis remplacez les nœuds. Pour tout exécuter d'un coup : Maj + F7 (Execute all).

Annexe A : Régénérer le jeu de données 
Si vous n'avez plus le fichier data/transactions.csv du TP04, recréez-le avec ce script (celui des TP2 
et TP04). Il nécessite Python avec numpy et pandas : utilisez l'environnement de votre TP04 ou un 
environnement neuf. 
 donnees.py 
import numpy as np 
import pandas as pd 
  
rng = np.random.default_rng(7)         # graine fixe : meme jeu pour toute la promo 
n = 5000                               # nombre de transactions 
montant = np.round(rng.lognormal(6.2, 1.1, n), 2)   # beaucoup de petits montants 
anciennete = rng.integers(0, 120, n)   # anciennete du client en mois 
freq = rng.poisson(3, n) + 1           # transactions sur 24 h 
nuit = rng.binomial(1, 0.18, n)        # paiement entre 0 h et 5 h 
score = 2.2*(np.log10(montant)-3.0) - anciennete/60 + (freq-3)/3 + nuit*1.2 
fraude = ((score + rng.normal(0, 0.35, n)) > 0.6).astype(int)   # etiquette 0 / 1 
  
df = pd.DataFrame({'montant': montant, 'anciennete': anciennete, 
                   'freq_24h': freq, 'nuit': nuit, 'fraude': fraude}) 
df.to_csv('data/transactions.csv', index=False) 
print('data/transactions.csv ecrit :', n, 'lignes,', fraude.sum(), 'fraudes')
