# Hypothèses et limites

- **Données** : exécution exacte de l’Annexe A avec NumPy default_rng(7), fichier CSV à fins de lignes LF et SHA-256 consigné. Les contrôles de données sont étiquetés simulation scikit-learn avec précision NumPy/pandas ; ce sont bien des transactions synthétiques.
- **Orange** : véritable API Orange 3.40.0, Python 3.13.3, NumPy 2.3.5, scikit-learn 1.9.1. Réglages relus dans les sources installées. Sampler et CV : graine 42 ; LR, RF et GB : random_state=0 comme leurs widgets ; kNN et Tree déterministes ici. Tous les scores attendus sont reproduits à trois décimales, sans recherche de paramètres destinée à les forcer.
- **Modèle** : format identique à Save Model, pickle.dump sans protocole imposé, recharge et prédictions contrôlées. Taille réelle 141461 octets contre environ 320 Ko annoncés ; cause exacte de l’écart de taille non établie. Ne pas déduire sa qualité de son poids. L’objet contient le domaine et les transformations Orange nécessaires à la prédiction.
- **Workflow Orange** : généré avec les API officielles orangecanvas/orangewidget, version des réglages explicite et pickle_fallback autorisé par le sérialiseur officiel pour conserver les contextes. Recharge ET exécution offscreen validées, cinq scores inchangés ; cible 1 persistée dans Test and Score et ROC. Les propriétés du File et des vues sont conservées. Vérification graphique et captures [À FAIRE PAR L'ÉTUDIANT]. Le chemin CSV peut demander une relocalisation après déplacement. Save Model conserve le chemin local du modèle et ne l’écrase pas automatiquement.
- **KNIME** : aucune commande, dossier courant ni entrée de registre trouvé lors de l’inventaire PowerShell ; recherche non exhaustive pour les installations portables. Aucune exécution KNIME ni capture réelle. La simulation scikit-learn utilise des attributs numériques bruts, LR max_iter=2000, RF 100 arbres, GB 100 arbres/profondeur 4/taux 0,1, graines 42. La LR simulée sous la plage indicative de l’énoncé reste conservée. Les résultats réels et .knwf sont [À FAIRE PAR L'ÉTUDIANT].
- **FLAML** : ../tp4-automl absent. Paramètres supposés selon la demande : partage NON stratifié 75/25, random_state=42 ; budget 60 s, seed=42, classification, f1, n_jobs=1. FLAML 2.7.0 a réellement exécuté une recherche ; le meilleur XGBoost et son F1 sont ceux de cette exécution. Une nouvelle recherche peut explorer d’autres configurations en fonction de la machine et du budget.
- **Comparaison** : test FLAML 134 fraudes ; tests Orange et simulation KNIME 142 fraudes, mais indices différents. Pas de test statistique ; un écart de 1 à 2 centièmes ne démontre pas une différence significative. L’étude du seuil est illustrative, avec 0,3 fixé avant calcul de la matrice, et ne constitue pas une optimisation métier validée.
- **CV** : cinq entraînements sur 4000 lignes chacun ; F1 Orange agrégé sur les prédictions hors pli. La moyenne des cinq F1 est également fournie et peut différer légèrement. Les jeux d’apprentissage se recouvrent ; les plis ne sont pas cinq expériences indépendantes.
- **Word** : créé et contrôlé structurellement, avec cinq placeholders de captures. Le rendu visuel a échoué faute de LibreOffice dans le runtime Windows ; aucun PDF/PNG du Word revendiqué. Vérifier toutes les pages manuellement. Le Word générique est local et ignoré par Git ; Markdown et scripts sont versionnés.
- **Installation** : première tentative interrompue par manque d’espace disque. Le cache de téléchargement pip, régénérable, a été purgé (environ 3,5 Go), puis les installations ont réussi sans cache, uniquement dans .venv et .venv-orange. Aucune installation globale, aucune GUI bloquante.
- **Git** : dossier initial non Git, initialisé sur main et lié au distant demandé. git ls-remote a confirmé un distant vide ; aucun pull n’était applicable. Le premier accès sous restriction réseau a échoué en résolution DNS, puis la vérification autorisée a réussi. Aucun push force ni réécriture d’historique. Tous les pushes des phases ont réussi.
